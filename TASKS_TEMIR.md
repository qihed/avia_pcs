## Принятые правила

На скриншоте нет подробной спецификации UrgencyLevel. Использовано следующее допущение, которое можно изменить в `domain/UrgencyLevel.java`:

| До вылета | Уровень |
| --- | --- |
| больше 72 часов | LOW |
| больше 24, до 72 часов включительно | MEDIUM |
| больше 6, до 24 часов включительно | HIGH |
| больше 0, до 6 часов включительно | CRITICAL |
| вылет наступил, бронь архивная либо COMPLETED/CANCELLED/EXPIRED | NONE |

Время рейсов хранится и показывается как UTC. Срочность вычисляется при выдаче данных, не сохраняется в БД.

Сохранены правила консольного приложения: CREATED без оплаты истекает через 30 минут при обращении к API броней; отмена разрешена не позднее чем за 2 часа до вылета; менять место, тариф и цену можно только у CREATED/PAID. Пассажир и рейс существующей брони неизменяемы. Схема мест — шесть кресел A–F в ряду, количество мест ограничено вместимостью самолёта.

Архивировать можно COMPLETED/CANCELLED/EXPIRED. Восстановление возвращает запись из архива и сохраняет её статус. Архив не служит способом отмены действующей брони.

Окончательное удаление: только ADMIN, только из архива и только при `PERMANENT_DELETE_ENABLED=true`. По умолчанию настройка выключена. Вместе с бронью удаляются её заметки и теги.

Миграции V1/V2 не изменялись, новые таблицы и поля не потребовались. JPA использует существующую UUID-схему.

## API

| Метод | Путь | Действие |
| --- | --- | --- |
| GET | /api/items?archived=false&page=0&size=20 | Список; страницы с нуля, размер до 100 |
| GET | /api/items/{id} | Карточка |
| POST | /api/items | Создание (201) |
| PUT | /api/items/{id} | Изменение, обязательна текущая version |
| PATCH | /api/items/{id}/status | `{ "status": "PAID", "version": 0 }` |
| DELETE | /api/items/{id}?version=0 | Перенос в архив |
| POST | /api/items/{id}/restore | `{ "version": 1 }` |
| DELETE | /api/items/{id}/permanent?version=2 | Окончательное удаление (204) |
| GET / POST | /api/items/{id}/notes | Список / создание заметки |
| PUT / DELETE | /api/items/{id}/notes/{noteId} | Изменение / удаление |
| GET / POST | /api/references/passengers | Список / создание |
| GET / PUT / DELETE | /api/references/passengers/{id} | Чтение / изменение / удаление |
| GET / POST | /api/references/flights | Список / создание |
| GET / PUT | /api/references/flights/{id} | Чтение / изменение (с version) |
| DELETE | /api/references/flights/{id}?version=0 | Удаление |

Заметка: `{ "text": "Позвонить пассажиру", "pinned": true }`; от 1 до 2000 символов, пробельный текст запрещён.

Бронь: `passengerId`, `flightId` (UUID), `seatNumber`, `fareClass` (ECONOMY/COMFORT/BUSINESS), `price`, `extraBaggage`; для изменения — `version`.

Все операции используют существующую JWT-авторизацию. Ошибки возвращаются в едином формате проекта. `VERSION_CONFLICT` означает необходимость перечитать запись; повторной отправки с подменённой версией клиент не делает.

## Запуск

Требуются JDK 21, Node.js/npm, PostgreSQL или Docker Desktop. Найденная системная Java 8 не подходит.

1. Скопировать `.env.example` в `.env`, задать пароли и JWT_SECRET_BASE64.
2. Из корня проекта: `docker compose --env-file .env -f backend/docker-compose.yml up -d --build --wait` (или существующий `backend/start-compose.ps1`).
3. В `web`: `npm ci`, затем `npm run dev`.
4. Открыть http://localhost:5173, войти с данными BOOTSTRAP_ADMIN_EMAIL / BOOTSTRAP_ADMIN_PASSWORD и сменить временный пароль.
5. Для редактирования справочников нужна роль ADMIN. В справочниках создать пассажира и будущий рейс, затем открыть «Брони» → «Новая бронь».

Без Docker backend запускается через `backend/mvnw.cmd spring-boot:run` при настроенных переменных подключения к PostgreSQL и авторизации из `.env.example`. Сам Maven не читает `.env` автоматически — переменные нужно передать окружению процесса.
