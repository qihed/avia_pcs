# Прогон тест-кейсов TC-01…TC-16

Все тексты ниже сняты с работающего приложения (`console-app/target/avia-booking.jar`) на свежих
демонстрационных данных. PNR новых броней и даты рейсов у вас будут другими.

## Подготовка

Перед прогоном верните исходный набор данных: брони в статусе «Создано» аннулируются через 30 минут (BR-09).
Приложение перед сбросом нужно закрыть.

```bash
cd console-app
./start-compose.sh     # если PostgreSQL ещё не запущен
./reset-demo.sh        # ввести RESET: схема avia удаляется вместе с историей Flyway
./run.sh               # первый запуск заново создаёт схему (V1) и демо-данные (V2)
```

Windows: `.\start-compose.ps1`, `.\reset-demo.ps1`, `.\run.ps1`.
Вместо `run.sh` можно запустить собранный jar: `./mvnw clean package`, затем `java -jar target/avia-booking.jar`
(из каталога `console-app`, чтобы приложение нашло `.env`). Как поднять окружение с нуля — [QUICKSTART.md](QUICKSTART.md).

Обозначения:

- `3 → 1` — в главном меню пункт 3, затем пункт 1. Ввод `⏎` — просто Enter.
- В любом диалоге ввод `0` отменяет операцию: выводится `Операция отменена`, и открывается то же меню.
- После выполненной операции приложение ждёт Enter: `Нажмите Enter для возврата в меню...`
- Ошибка команды выводится строкой `  Операция не выполнена [E-xxx]: текст`, запись при этом не меняется.
- Ошибка в поле диалога операцию не прерывает, поле запрашивается снова:
  `  Ошибка: ID должен быть целым числом. Повторите ввод.` (ошибки формата E-1xx),
  `  Пассажир с ID 42 не найден. Повторите ввод.` (остальные),
  `  Место 14C на рейсе SU1420 уже занято. Выберите другое место.` (занятое место).

TC-04…TC-13 можно пройти подряд в одном сеансе; где предыдущий шаг влияет на результат, это указано.
Перед TC-14 и TC-16 снова выполните `./reset-demo.sh`.

Даты рейсов в демо-данных считаются от дня загрузки (Д — сегодня):

|---|---|---|---|---|
| 1 | SU1416 | SVO → LED | Д−8, 08:40 | Прибыл |
| 2 | SU1102 | SVO → AER | Д−6, 19:05 | Прибыл |
| 3 | SU1420 | SVO → LED | Д+1, 08:40 | По расписанию |
| 4 | SU1421 | LED → SVO | Д+1, 19:20 | По расписанию |
| 5 | SU1108 | SVO → AER | Д+7, 19:05 | По расписанию |

### TC-02. Запуск при остановленной СУБД (E-501)
Остановить PostgreSQL (`./stop-compose.sh` в `console-app`) и запустить приложение.
**Ожидается:**
```
  Подключение к базе данных...
  Операция не выполнена [E-501]: Нет связи с базой данных. Проверьте, запущен ли сервер PostgreSQL
    1. Повторить попытку
    0. Выход
  Выберите действие:
```
Стека вызовов нет. Запустить СУБД в другом терминале (`./start-compose.sh`), ввести `1` — приложение
подключится, выведет памятку и главное меню. Ввод `0` вместо этого завершает программу строкой
`Соединение с базой данных закрыто. До свидания!`.

Дополнительно: остановить СУБД во время работы (`docker compose stop db` в `console-app`) и открыть `3 → 2`:
```
  СПИСОК БРОНИРОВАНИЙ
  Операция не выполнена [E-501]: Нет связи с базой данных. Проверьте, запущен ли сервер PostgreSQL (correlation ID: 7ca04f57)
```
Приложение продолжает работу, в заголовке главного меню вместо счётчиков —
`Нет связи с базой данных — счётчики недоступны`. После `docker compose start db` команды снова работают:
соединение открывается заново для каждой операции.

> К ошибкам E-5xx добавляется `(correlation ID: xxxxxxxx)` — первые 8 символов идентификатора команды.
> По нему в `console-app/avia-booking.log` находится строка с техническими подробностями, например
> `WARN ConsoleErrorHandler - Database unavailable, correlationId=7ca04f57-…, command=bookings.list`.

### TC-09. Отмена брони незадолго до вылета (BR-08)
Бронировать рейс, до вылета которого меньше 60 минут, нельзя (BR-01), поэтому:
1. `2 → 1` — добавить рейс: `TT0001` ⏎ `Тест` ⏎ `SVO` ⏎ `LED` ⏎ вылет **через 1,5 часа** от текущего времени
   (`дд.ММ.гггг ЧЧ:мм`) ⏎ прилёт на час позже ⏎ `Airbus A320` ⏎ `180` ⏎ `5000`.
   Результат: `  Рейс добавлен, ID = 9: TT0001, SVO -> LED, <вылет>`.
2. `3 → 1` — бронь на этот рейс: `1` ⏎ `9` ⏎ `1` ⏎ `1A` ⏎ `нет` ⏎ `да`
   (`Расчёт стоимости: 5 000,00 x 1.0 = 5 000,00 руб.`). На свежих данных новая бронь получает ID 15.
3. `3 → 6` — ввести `15` или PNR новой брони.

**Ожидается** (вопрос «Отменить бронь?» не задаётся):
```
    Бронь FQQNEM, Иванов И. И., рейс TT0001 SVO -> LED 17.09.2026 22:03, место 1A, текущий статус: Создано, ожидает оплаты
  Операция не выполнена [E-304]: Отмена невозможна: до вылета осталось менее 2 часов
```
Статус не изменён. Чтобы показать ровно «за 30 минут», после шага 2 сдвиньте вылет в БД и повторите шаг 3 —
сообщение то же:
```bash
cd console-app
docker compose exec -T db psql -U avia_app -d avia_booking -c "UPDATE avia.flights SET departure_time = now() + interval '30 minutes', arrival_time = now() + interval '2 hours' WHERE flight_number = 'TT0001';"
```
(`avia_app` — значение `POSTGRES_USER` из `.env`; для установленного PostgreSQL — `psql -U postgres -d avia_booking -c "…"`.)

### TC-14. Поиск, фильтрация и сортировка (FR-12…FR-14)

## Умный фильтр (`5 → 9`)

Строка запроса задаёт выборку целиком (заменяет фильтры пунктов 1–5), сортировка сохраняется.
Условия объединяются через «И», регистр не важен, ключи можно писать по-русски или по-английски.
Полный список примеров — [examples/smart-filter-queries.txt](../examples/smart-filter-queries.txt).
Перед вводом экран печатает подсказку:
```
  --- УМНЫЙ ФИЛЬТР ---   (0 — отмена и возврат в меню)

  Условия «ключ:значение» объединяются через «И», регистр не важен:
    статус:оплачено  активные:да  класс:бизнес  рейс:SU1420
    откуда:SVO  куда:LED  пассажир:иванов
    с:01.10.2026  по:15.10.2026  цена>=15000  цена<10000
  Ключи можно писать по-английски: status, active, class, flight,
    from, to, passenger, since, until, price
  Слово без ключа ищется в номере брони, фамилии и номере рейса
  Пример: статус:оплачено класс:бизнес
  Пустая строка снимает все фильтры, сортировка сохраняется
```

На свежих данных:

| Строка запроса | Ожидается |
|---|---|
| `статус:оплачено класс:бизнес` | `Выборка: 1 из 14 броней` (HG23KL); `Фильтры: статус: Оплачено; класс: Бизнес` |
| `откуда:SVO активные:да цена<10000` | 4 брони (RT58NB, PL66CX, DF52JU, KJ90XZ); `Фильтры: статус: только активные; откуда: SVO; стоимость меньше 10 000,00` |
| `иванов` | 3 брони (AB12CD, LM77PQ, OS44BN); `Фильтры: поиск: иванов` |
| `status:paid` | 5 броней, как `5 → 1` `2` |
| ⏎ (пустая строка) | `Выборка: 14 из 14 броней`; `Фильтры: нет` |

Ошибочная строка не закрывает диалог — выводится причина и строка запрашивается снова (`0` — отмена):

| Строка запроса | Ответ приложения |
|---|---|
| `статус:неизвестно` | `  Ошибка: неизвестный статус: неизвестно. Повторите ввод.` |
| `класс:первый` | `  Ошибка: неизвестный класс обслуживания: первый. Повторите ввод.` |
| `активные:может` | `  Ошибка: поле «активные» принимает да/нет. Повторите ввод.` |
| `с:31.02.2026` | `  Ошибка: такой даты не существует: 31.02.2026. Повторите ввод.` |
| `с:31.12.2026 по:01.12.2026` | `  Ошибка: дата «с» не может быть позже даты «по». Повторите ввод.` |
| `цена>=100 цена<=50` | `  Ошибка: минимальная сумма не может быть больше максимальной. Повторите ввод.` |
| `откуда:Москва` | `  Ошибка: код аэропорта должен состоять из трёх латинских букв, например SVO. Повторите ввод.` |
| `рейс:SU14166` | `  Ошибка: номер рейса должен иметь вид SU1416 (код авиакомпании и 1–4 цифры). Повторите ввод.` |

## Дополнительные проверки (п. 11.1 ТЗ)

**Устойчивость ввода:**

| Действие | Ввод | Ответ приложения |
|---|---|---|
| `1 → 1`, фамилия | ⏎ | `  Ошибка: фамилия пассажира не может быть пустой. Повторите ввод.` (E-104) |
| `1 → 1`, дата рождения | `31.02.2026` | `  Ошибка: такой даты не существует: 31.02.2026. Повторите ввод.` (E-102) |
| `1 → 1`, e-mail | `ivanov@` | `  Ошибка: E-mail должен иметь вид name@example.com. Повторите ввод.` (E-103) |
| `3 → 1`, место (`2` ⏎ `5` ⏎ `1`) | `12G` | `  Ошибка: номер места должен иметь вид 12A (ряд и буква A–F). Повторите ввод.` (E-103) |
| главное меню | `9` | `  Ошибка: выберите пункт от 0 до 8.` (E-105), меню выводится снова |

**Таблицы БД** (`8 → 1`, `8 → 2`, `8 → 3`): строки выводятся как есть (`Таблица passengers (Пассажиры)`,
`Всего строк в таблице: 6`), но `document_number` маскирован: `45 10 ****56`, `75*****56`, `VIII-MU-****56`, `C0*****47`.
Больше 20 строк выводятся страницами: `Страница 1 из N · … Enter — следующая страница, 0 — завершить просмотр:`.

**Целостность БД:** все команды скрипта завершаются ошибкой ограничения (14 ERROR), число записей не меняется.
```bash
cd console-app
docker compose exec -T db psql -U avia_app -d avia_booking < sql/integrity_check.sql
# установленный PostgreSQL: psql -U postgres -d avia_booking -f console-app/sql/integrity_check.sql
```

**Архитектура:** SQL только в `repository/impl`, консоль только в `ui`. Из корня репозитория:
```bash
grep -rnE '"[^"]*\b(SELECT|INSERT|UPDATE|DELETE)\b' --include='*.java' console-app/src/main/java | grep -v /repository/impl/
grep -rnE 'System\.(out|err|in)|Scanner|PrintStream' --include='*.java' console-app/src/main/java | grep -v /ui/
```
Обе команды ничего не выводят. Те же и другие ограничения проверяет `scripts/verify.py` (ниже).

**Модульные тесты (JUnit 5 + AssertJ):** `cd console-app && ./mvnw test` — сборка должна завершиться `BUILD SUCCESS`.

## Проверка проекта `scripts/verify.py`

```bash
python3 scripts/verify.py           # статические проверки, несколько секунд
python3 scripts/verify.py --build   # плюс ./mvnw clean verify и docker compose config (логи в build-reports/)
```

Скрипт печатает итог `PASS=… FAIL=0 SKIP=…; report=…/VERIFICATION.md` и завершается с кодом 0, если провалов нет.
В `VERIFICATION.md` — таблица проверок: обязательные файлы, число Java-файлов и JavaDoc, отсутствие
Spring/JPA/JavaFX/Hibernate/Lombok, SQL только в `repository/impl`, консоль только в `ui`, отсутствие конкатенации
SQL и `createStatement(`, отсутствие паролей в коде и конфигурации, отсутствие TODO/FIXME, класс ≤ 300 строк,
метод ≤ 40 строк, все коды ошибок в `ErrorCode`, совпадение `sql/schema.sql` с V1 и `sql/data.sql` с V2,
маркер и порт в `docker-compose.yml`, поиск известных форматов секретов. Рядом обновляется
`SOURCE_MANIFEST.sha256` — контрольные суммы исходников. `SKIP` означает, что в среде нет нужного
инструмента (например, Docker для `--build`). Тот же скрипт запускает CI.
